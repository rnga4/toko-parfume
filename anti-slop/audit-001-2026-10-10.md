# Audit 001, 2026-10-10

- Mode: antislop AFTER (audit, read-only sampai ada persetujuan).
- Ruang lingkup: seluruh UI `app/src/views/*.ejs` plus gaya inline di `header.ejs` dan `struk.ejs`.
- Alat: skill `design` + `ui-ux-pro-max` (script pencarian lokal) untuk panduan UX, lalu filter `antislop` (core, ui, human, layoutmobile, copywriting) untuk temuan.
- Status verifikasi: belum dijalankan (server Express + Postgres tidak dinyalakan). Semua temuan diperiksa lewat inspeksi kode. R-35 belum dijalankan.
- Catatan skill: `--design-system` mengembalikan pola landing page (Hero + fitur + CTA) yang tidak relevan untuk ERP internal. Arah desain proyek ini sudah ada di `DESIGN.md`, jadi audit memakai `DESIGN.md` sebagai arah dan data UX `ui-ux-pro-max` sebagai rujukan.

## Prioritas

- HIGH: melanggar Hard Gate.
- MEDIUM: melanggar Purpose-Gate atau rekomendasi UX ber-severity High.
- LOW: Quality Lock / rekomendasi UX ber-severity Medium.

## Temuan

1. **HIGH, R-38 + R-23.** Data seed dan kredensial default ikut tampil sebagai data nyata.
   Lokasi: `db/init.sql` (seed Dior Sauvage, YSL Libre), `app/src/lib/migrate.js` (akun `admin` / `admin123`), tampil di `products.ejs` dan `kasir.ejs`.
   Alasan: konten yang terlihat nyata ada di DB produksi tanpa label placeholder, dan `DESIGN.md:141-143` sudah menandai ini sebagai prasyarat go-live.

2. **MEDIUM, ui-ux-pro-max UX "Input Labels" (severity High).** Semua field memakai placeholder sebagai satu-satunya label yang terlihat.
   Lokasi: `login.ejs:10-11`, `products.ejs:12-32`, `product-edit.ejs:13-32`, `kasir.ejs:22-27,96-108`, `purchase-new.ejs:18-24,52-57,103-113`, `suppliers.ejs:12-14`, `customers.ejs:12-14`, `users.ejs:15-17,53-62`, `opnames.ejs:27`, `opname.ejs:43`.
   Alasan: input punya `aria-label`, tetapi tidak ada `<label>` yang terlihat, jadi petunjuk menghilang begitu diisi. Skill menilai "Always show label above or beside input, don't: placeholder as only label" (High).

3. **MEDIUM, ui-ux-pro-max UX "Color Only" (severity High) + C-4.** Status peringatan hanya dibedakan warna merah.
   Lokasi: `header.ejs:65` (`.warn`), `products.ejs:54` (stok di bawah minimum merah tanpa teks/ikon), kartu "Stok Menipis" di `dashboard.ejs:9`.
   Alasan: pengguna low-vision/color-blind tidak punya penanda non-warna untuk stok di bawah minimum. Panduan: "Use icons/text in addition to color" (High).

4. **MEDIUM, ui-ux-pro-max UX "Focusable Error Summary" (severity High).** Galat form tidak dipusatkan dan tidak menautkan ke field.
   Lokasi: `.alert` di `kasir.ejs:5`, `products.ejs:4`, `purchase-new.ejs:4`, `suppliers.ejs:4`, `customers.ejs:4`, `product-edit.ejs:6`, `users.ejs:4`, `decants.ejs:4`, `opnames.ejs:4`.
   Alasan: `role="alert"` sudah dipakai, tetapi kontainer tidak `tabindex="-1"`, fokus tidak dipindah ke ringkasan galat, dan field bersangkutan tidak ditandai. Panduan: "Place it at the top of the form; move focus to its heading; link each item to its invalid field; retain inline errors" (High).

5. **MEDIUM, R-03 (antislop-layoutmobile "Two-State Layout").** Tidak ada state tablet, hanya dua titik.
   Lokasi: `header.ejs:88-91` (`.grid` melompat dari 1 kolom ke 5 kolom tepat di 700px) dan `header.ejs:92-104` (`.stack` hanya aktif di bawah 640px).
   Alasan: di 641-767px tabel desktop padat tetap dipakai (mis. `sales.ejs` 9 kolom) dan grid sudah/akan melompat tanpa state antara, padahal R-03 menuntut layout bertahan di seluruh rentang lebar.

6. **LOW (dampak tinggi), R-05 + R-14.** Kolom grid kosong saat jumlah kartu tidak sesuai template.
   Lokasi: `header.ejs:89` menetapkan `.grid` `2fr 1fr 1fr 1fr 1fr` di >=700px; kasir melihat 4 kartu di `dashboard.ejs:3-11`; `hutang.ejs:7-10` dan `piutang.ejs:7-10` hanya 2 kartu.
   Alasan: 4 kartu menyisakan 1 kolom kosong dan 2 kartu menyisakan 3 kolom kosong, sehingga sekitar separuh lebar layar jadi ruang hampa. Jumlah kolom sebaiknya mengikuti jumlah kartu.

7. **LOW, C-1 (intentionality).** Klaim `DESIGN.md` tidak cocok dengan implementasi.
   Lokasi: `products.ejs:59`, `suppliers.ejs:44`, `opnames.ejs:16`, `opname.ejs:51`, `piutang.ejs:46`, `hutang.ejs:46` memakai `onsubmit="return confirm(...)"`, sedangkan `DESIGN.md:55` menyatakan tidak ada satu baris JS pun di klien. `kasir.ejs:27` dan `purchase-new.ejs:23` memakai input jumlah yang diketik, sedangkan `DESIGN.md:93` menyatakan jumlah hanya diubah lewat tombol minus dan plus.
   Alasan: arah desain tertulis bertentangan dengan kode, sehingga alasan tiap keputusan (R-31) tidak lagi akurat.

8. **LOW, ui-ux-pro-max UX "Skip Links" (severity Medium).** Tidak ada tautan lewati navigasi.
   Lokasi: `header.ejs:110-141`.
   Alasan: navigasi muncul di setiap halaman, jadi pengguna keyboard harus melewati seluruh menu setiap kali pindah halaman. Panduan menyarankan "Skip to main content link".

9. **LOW, R-32.** Toggle sidebar tidak mengumumkan status buka/tutup.
   Lokasi: `header.ejs:113-114`.
   Alasan: checkbox + label tanpa `aria-expanded`/`aria-controls`; pembaca layar tidak diberi tahu bahwa sidebar terbuka. Menutup dengan Escape juga tidak ada, dan ini sudah diakui di `DESIGN.md:75`.

### Tambahan 2026-10-11: micro-interaction (persetujuan user)

User meminta animasi "untuk semua"; setelah diklarifikasi, ruang lingkupnya micro-interaction bertujuan (hover/fokus/tekan, slide sidebar, fade galat), bukan animasi dekoratif, dan `prefers-reduced-motion` tetap dihormati. Interaksi-proof dicerahkan pada `button:hover`, `.btn:hover`, `button.danger:hover` (ganti dari `:active` saja); `:active` tombol turun 1px. Sidebar kini menyelinap dengan `transform` 200ms, penghalangnya memudar 200ms, dan saat tertutup `visibility:hidden` agar tidak ikut Tab. `.alert`/`.flash` memudar masuk 250ms sekali pakai. Skip link punya transisi 150ms. `@media (prefers-reduced-motion:reduce)` mematikan semua animasi dan transisi. `DESIGN.md` bagian Motion (R-19) disesuaikan. Semua perubahan CSS di `header.ejs` (satu titik berlaku ke semua view); app yang berjalan otomatis memuat ulang lewat bind mount `node --watch` (terverifikasi dari respons `/login`).
